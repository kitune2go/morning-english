# 日次対話エッセイ：対訳と文脈の品質監査

## 適用範囲

`literature/daily-essay-YYYYMMDD/essays-*.json` の `jp`（日本語原文）、`translationLiteral`（直訳）、`translationNatural`（自然な英訳）、`chunks[].en/ja`（英文とその対訳）、`grammar`、`translationNote`、`literature/essay-context-glossary.json`（単語・句の文脈訳）が対象。

## 公開前の照合順序（すべて必須）

1. **意味単位を抽出**：`jp` の各文について「誰が、何を、誰へ、いつ、どの条件で、なぜ、どの程度」を明記する。否定・例外・順序・対比・単位・結論・比喩も含める。
2. **二種類の英訳を別々に監査**：literal と natural の両方について、各意味単位の対応先を照合する。文章を自然に整えることは許すが、主体・所有関係・時制・条件・因果をずらさない。省略した結末や勝手に付け足した固有数値があれば差し戻す。
3. **逆翻訳と再照合**：自然な英訳だけを読んで日本語に戻し、原文と比較する。逆翻訳の一致だけでは不十分なので、主語・否定・条件・原因と結果・人物の役割を別途点検する。
4. **チャンクごとに訳す**：`chunks[].en` は順に連結すると `translationNatural` の全文にならなければならない。各 `chunks[].ja` は、その `en` 自体を正確に訳す（日本語原文を安易に切り貼りしない）。論理接続詞、照応表現、否定を前後のチャンクと通読する。
5. **語義・解説を合わせる**：文学的・技術的語、動作主体、慣用句、重要な多義語には作品固有の `words` と `phrases` の文脈注釈を付ける。辞書の「一般語義」をその文の「正しい文脈訳」と混同しない。表現を改稿した場合、文脈単語帳、文法、翻訳メモも同時に修正する。
6. **独立した校閲**：英文だけ読んだ際に主張が変わらないか再評価する。意味上の重大な違いが1件でもあれば公開しない。品質が不確かな場合も保存・索引登録を見送る（定期タスクは止めない）。

## 特に混同しやすい例

| 日本語 | 区別すべき表現 | よくあるずれ |
|---|---|---|
| 社長 / 所有者 / 創業者 | company president / owner / founder | 立場を勝手に入れ替える |
| 農地を託す | entrust land / make land available | open the land（開墾した）にしてしまう |
| 加工基準 / 機械原点 | machining datum / machine origin | 基準と座標原点を同一視する |
| 〜しなければ、〜になる | If it does ... など、直前の指示対象を明確にする | Otherwise / そうでなければ、の参照先を誤る |
| 原文の最後の比喩 | 自然訳にも意味を残す | 自然訳で結論だけ省いてしまう |

## 自動チェックと限界

`node scripts/validate-essay-translations.mjs` は最近の日次エッセイについて、英語チャンクの漏れ、順序・本文不一致、空の対訳などを検出する。単語と句の登録は `node scripts/validate-literature-glossary.mjs` でも検査する。

**機械的なJSON検証だけでは、自然な誤訳・話者の取り違え・条件の逆転・一般語義の誤用は発見できない。** 必ず人間の校閲に相当する意味監査を併用する。品質監査の実施を生成作業の完了条件とする。
